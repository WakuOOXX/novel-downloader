# 「书名/作者/分类/最新章节」字段规范化 —— GitHub 成熟项目调研与规则建议

> 针对聚合 3393 书源时同一本书的五列字段（书名/作者/分类/最新章节/书源）显示混乱的问题。
> 调研方式：定位本地 `bookdl` 字段来源 → GitHub 检索书源生态与元数据规范 → 提炼可直接落地的规则模板。
> 调研日期：2026-09-08

---

## 0. 结论（TL;DR）

1. **混乱的根因不在"缺清洗规则"，而在"每个源各自为政 + 缺统一的字段模型"**。同书不同源返回的记录无法被识别为同一本书，字段口径互不相通，展示层只能原样罗列。
2. GitHub 上没有"一本万能书"直接解决该问题，但有**两层成熟参照可抄**：
   - **字段模型与清洗规则**：抄 Legado（gedoor/legado）官方规则引擎及其 Python 移植版 **LegadoParser** 的 `FormatUtils.py`（`Fmt` 类）——它就是"书名/作者/分类/最新章节清洗"的现成规则实现，正则模板可直接摘录。
   - **多源结果去重合并**：抄 Legado 官方 `SearchModel.kt`——以 **书名+作者归一化键** 做同书分组，再在组内选最优字段展示、保留多源候选。
3. 建议落点（按投入产出排序）：
   - **P0（立即收益）**：把现有零散正则清洗收敛成一张"字段规则表"（见 §4），并增加**同书合并层**：`归一化(书名)+归一化(作者)` 作为合并键，组内按来源可信度选主显字段，其余源折叠为候选。
   - **P1**：下载前对目标源强制校验字段完整性（书名非空、作者缺失打标），把"最新章节"改在**详情页规则（ruleBookInfo）**取而非仅依赖搜索列表。
   - **P2**：如需对外暴露书源/书目数据，套用社区书源仓库规范（repository.json）保持字段语义稳定。

## 1. 本地现状：字段从哪来、为什么乱

### 1.1 数据流

```
书源JSON(ruleSearch/ruleBookInfo规则)
   → legado/engine.py search_sources(): rules.extract_value() 按各源规则抽值
   → _clean_name/_clean_author/_clean_kind/_clean_last 启发式清洗(engine.py L53-122)
   → 结果表五列: name/author/kind/last_chapter + source  (app.py L197-201)
```

### 1.2 混乱的具体成因（本地实测）

| 成因 | 证据 | 后果 |
|---|---|---|
| **各源字段键不齐** | 对 `shuyuan/shuyuan.json` 22 个本地源统计：`ruleSearch` 有的含 `kind/lastChapter/wordCount`，有的（番茄小说2）完全不含 | 展示列空缺 → 同一本书部分行有分类、部分没有 |
| **抽到错列/整块文本** | 部分站点规则抽出的 name/author/kind 互相污染（作者栏抽成书名前缀、分类栏抽到"作者/最新章节/字数"整行） | 单行字段错位，排序/去重逻辑失真 |
| **站名/SQL 尾巴** | 书名带"TXT下载/全文阅读/最新章节/无弹窗"等 SEO 尾巴 | 同书名字面不同 → 无法去重 |
| **同书多源不合并** | engine.py L269-277 仅做"同源同 URL"去重；跨源同名同作者的书**各显示一行** | 用户眼里同一本书 20 行、每行字段长得不一样 = "混乱"主来源 |
| **分类无统一口径** | 各站分类体系独立：玄幻/奇幻/都市/言情… 无规范词表 | 无法聚合统计 |

> 结论：本地已有的 `_clean_*` 四函数方向正确但属于"症状级补丁"，缺的是 (a) 结构化字段规则、(b) 跨源实体合并。

## 3. 推荐架构：三层模型（从源数据到展示）

```
Layer0 源数据:  各书源 ruleSearch/ruleBookInfo 抽出的原始字符串
Layer1 字段清洗: 按"字段规则表"逐字段归一（§4 规则模板）
Layer2 实体合并: 归一化键 = norm(name) + norm(author) → 同书归组（§5）
Layer3 展示:    组内选主字段 + 折叠其余源；组间按相关度排序
```

关键认知：**清洗解决"单行脏"，合并解决"多行乱"，两者缺一不可**。本地现在只有 Layer1 的一半。

## 4. 字段规则模板（可直接落地）

### 4.1 抄自 LegadoParser `Fmt` 类的"最小可信规则"（已验证源码）

```python
# 来源: https://github.com/821938089/LegadoParser/blob/main/LegadoParser2/FormatUtils.py
# 作者: 阅读3.0规则引擎Python移植, 与本地 bookdl 的清洗函数同思路但更克制

import re, unicodedata

class Fmt:
    # 书名: 去掉"作者"/"XX 著"尾巴(SEO混排常见)
    bookNameRegex = re.compile(r'\s+作\s*者.*|\s+\S+\s+著')
    # 作者: 去"作者:"前缀 与 "著"尾缀
    authorRegex = re.compile(r'^\s*作\s*者[:：\s]+|\s+著')
    spaceRegex  = re.compile(r'&nbsp;|&ensp;|&emsp;')
    noPrintRegex= re.compile(r'&thinsp;|&zwnj;|&zwj;')

    @classmethod
    def bookName(cls, text):          # 书名清洗
        return cls.bookNameRegex.sub('', text).strip()

    @classmethod
    def author(cls, text):            # 作者清洗
        return cls.authorRegex.sub('', text).strip()

    @classmethod
    def wordCount(cls, text):         # 字数: 纯数字>1万 → "x.x万字"
        if not text: return ''
        try:
            n = int(text)
            return f'{n/10000.0:.1f}万字' if n > 10000 else f'{n}字'
        except Exception:
            return text
```

> 对照评价：本地 `engine.py` 的 `_clean_*` 覆盖的尾巴清单（TXT下载/全文阅读/最新章节…）**比 Fmt 更激进**，对小站 SEO 尾巴有效，两者应**合并为一条规则链**而不是互相替代。

### 4.2 推荐"字段规则表"（统一 5 列口径）

给每个字段定义：`清洗链 + 合法形态 + 错值置空条件`。建议沉淀为独立规则模块（如 `legado/normalize.py`），GUI 与引擎共用。

| 字段 | 清洗链（按序执行） | 合法形态 | 判定为错值 → 置空 |
|---|---|---|---|
| **name 书名** | 1) 折叠空白 2) 截断误混入的"作者:/最新章节"起始位 3) 循环剥 SEO 尾巴（TXT下载/全文阅读/无弹窗/免费下载/(完结)/…） 4) 剥站名 `-xxx小说网` | 2~40 字，不含 URL/换行 | 含"最新章节/章节目录"整行文本；与作者相同 |
| **author 作者** | 1) 去"作者:"前缀 2) 去"著"尾 3) 折叠空白 | 2~12 字，中文姓名形态 | 与书名相同/为书名前缀；含"分类/章节/字数"关键词（错列）；含 `《》`（抽成书名了） |
| **kind 分类** | 1) 去"分类:"前缀 2) 折叠空白 3) 多值以 `/` 或 `,` 分隔展示 | 短词（玄幻/都市/科幻…）≤12 字 | 含"作者/最新章节/字数/更新/状态"等词；与书名相同 |
| **lastChapter 最新章节** | 1) 折叠空白 2) 若以书名开头则剥离书名 | ≤40 字，形如"第 N 章 xxx" | 含"作者/分类"等错列词；>60 字（抽到整块） |
| **wordCount 字数（如启用）** | 数字转 `x.x万字`；`xxx字` 中文原样 | 纯数字 / `xx.x万字` / `xxxx字` | 含非数字杂文 |

> 关键点：**字段"置空"优于"存脏"**。置空后同书合并层不会因垃圾值误拆组，GUI 也能明确显示"该源未提供分类"而不是展示一串乱码。

### 4.3 分类词表（可选 P2，用于聚合统计）

若要做"按分类统计"，从起点/番茄/晋江官方分类接口抓取三级分类词表，落一个 `kind_vocab.json`，归一化时先把站点分类**映射到主类**（如 东方玄幻→玄幻、游戏竞技→都市）。GitHub 无权威统一词表（分类本就是站方运营口径），此层只能自建映射、维护成本高，非必须。

## 5. 同书合并规则（解决"多行乱"的核心）

参照 Legado `SearchModel`（同书同作者去重）与书籍匹配讨论（bookId 优先），给出分级合并键：

```python
def norm_key(name, author):
    """同书判定键: 归一化书名 + 归一化作者。"""
    n = re.sub(r'[（(【\[].*?[)）】\]]', '', name or '')   # 去括号内容(卷标/副标题)
    n = re.sub(r'[\s:：\-—_|/\\·,，。、\'"“”]+', '', n).lower()
    a = re.sub(r'[\s·]+', '', author or '') or '(无名)'
    return (n, a)

def merge_hits(hits):
    """把跨源命中按同书分组; 组内保持多源候选供下载探测。"""
    groups = {}                     # key -> {meta: 主字段, sources: [...]}
    for h in hits:
        k = norm_key(h['name'], h['author'])
        g = groups.setdefault(k, {'name': h['name'], 'author': h['author'],
                                   'kind': '', 'last': '', 'sources': []})
        # 择优填充组内主字段: 取非空且更短的分类/最新章节
        if not g['kind'] and h.get('kind'):
            g['kind'] = h['kind']
        if not g['last'] and h.get('last_chapter'):
            g['last'] = h['last_chapter']
        g['sources'].append(h)
    return list(groups.values())
```

规则要点：
1. **同书键 = 去括号/标点的书名 + 作者**；同源内若详情页 URL 含稳定 bookId（如 `book/12345.html`），同源内优先用 bookId 合并，跨源才退回书名+作者。
2. **组内主字段择优**：kind/lastChapter 取组内首个非空；若多个源值冲突，可让"命中多个源的书"（即高可信书）的字段胜出。
3. **保留多源候选**：合并只是展示折叠，下载探测仍遍历组内所有源（现有 `selpolicy`/探测逻辑可复用），不损失源多样性。
4. **相关度排序在合并后做**：`_rel_score` 按组的主字段算，避免同书多行重复占用排序名额。
