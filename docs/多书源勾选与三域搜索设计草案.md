## 2. 现状关键事实(代码依据)

- 书源加载:`reload_sources(path)` 单文件;原始表=校验专用,搜索自动采用同目录 `<名>.good.json`(仅当 `verify_done.origin` 匹配才信任)。
- `self.sources` 为单文件展开的工作源列表;`source_groups()` 从中提取「书源分组」下拉。
- 命中去重键 = `(bookSourceName, book_url)`(engine.py L272),选中记忆键 `_hit_key` 相同。
- 搜索:`search_sources(sources, key)` 把 key 代入各源 `searchUrl` 模板的 `{key}`——**网络层只支持按书名**;「模糊搜索」=书名变体重试;「只看相关结果」=本地对已返回结果按 名称/作者/分类/最新章节/简介 打分过滤。
- 校验:`start_verify` 对单一原始表 64 并发 GET `bookSourceUrl`==200 → 写 good 表;`verify_origin/verify_done` 存 sel_state。
- 记忆写盘统一 `_mem_flush`(selected/fuzzy/rel/fmt/mode/verify_*)。

## 3. 架构设计

### 3.1 多文件状态模型(A)

```jsonc
// sel_state.json 增量(其余字段不变)
{
  "sources": ["bookSource.json", "shuyuan.json"],   // 勾选文件名(相对 shuyuan/),保序
  "verify_dones": {                                  // 每文件一条校验记录
    "bookSource.json": {"origin": "E:/.../bookSource.json", "time": 1788796855.8}
  }
}
```

- 启动 `_reload_all()`:按 `sources` 逐个 `load_sources` → 合并 enabled 源进 `self.sources`;每个源在内存附 `"_file"` 标记(不改书源 JSON),供日志/归属显示。
- good 信任平移:逐文件判定自己的 `.good.json` 是否被 `verify_dones` 信任 → 用 good;无信任 good → 该文件用全量并记日志降级。
- 旧文件迁移:无 `sources` 字段时取旧 `verify_origin` 的文件名,`verify_done`(单)→ `verify_dones[该文件]`。一次性、无损。
- 文件缺失/读取失败:**保留勾选**但标记(菜单项显示"缺失"),加载时跳过并日志提示——不替用户改勾选。

### 3.2 UI(C)

替换顶部一行:`书源文件: [Entry][选择…][重新加载]` → 

```
书源文件: [▾ 已勾选 2 / 6]  [打开目录]  [✔ 校验书源] …(校验按钮原位保留)
```

- 下拉载体:`ttk.Menubutton` + `tk.Menu`,每文件一项 `add_checkbutton`(菜单自带 ✔),顶部「全选 / 全不选」分隔,底部「选择其他文件…」(复制进 shuyuan/ 后勾选)。
- **每次点开前重扫** `shuyuan/*.json`(满足 R4 "随时增减",不做常驻监视——简单且无竞态)。
- 列表过滤 `*.good.json` / `*.error.json`(校验产物,非原始表,防误勾)。
- 勾选变化 → 立即合并重载 + 写 `sel_state.sources`(勾上即记、取消即记,与选项记忆同款"不改回"语义)。
- 「书源分组」下拉(源粒度)原样保留,分组天然按合并后的 sources 汇总。
- 理由:ttk.Combobox 只读不支持复选;tk.Menu 复选在 ttk 主题下工作正常,实现量最小。

### 3.3 校验多文件化(D)

- 编排:对勾选的**原始文件按序**逐个校验;文件内部沿用 64 并发;进度条文案 `文件 i/N · done/total`;`停止` = 当前文件中止 + 后续文件不再开始(已完成文件的 good 表保留)。
- 完成:lbl_verify 汇总 `已校验 N 文件 · 有效 x · 失效 y`;每文件写各自 good 表 + `verify_dones[文件]`。
- 降级:某文件校验后 0 有效/写入失败 → 沿用现有"旧表保留"语义,按文件独立处理。

### 3.4 命中键(B,风险项,建议 P1 再动)

跨文件同名书源(同名不同站)会让 `(bookSourceName, book_url)` 出现:
- 结果去重(engine L272):两个文件的同名源搜到同一书页 URL → 只留一行(行为可接受,但丢一个下载备选源);
- 选中记忆:键仍唯一(名+书URL),无实际错乱。

**P0 不动此键**(避免旧 selected 记忆全失效);P1 再升级为 `(bookSourceName, bookSourceUrl, book_url)` 并做旧记忆兼容映射。

### 3.5 三域搜索(E)

**物理限制(必须如实)**:数千书源的 `searchUrl` 模板只有书名 `{key}`,网络按作者/分类搜索不可行。

分层设计:

1. UI:标签 `书名:` → `搜索:`;输入框旁加小下拉 `书名 / 作者 / 分类 / 自动`(默认**自动**,记忆持久,与 fuzzy/rel 同机制)。
2. 网络层:关键词始终按书名发起(含模糊变体),不变。
3. 本地层(核心):
   - `自动`:现有 `_relevant/_score_hit` 打分升级——name 命中 +40、author +30、kind +20、intro/最新章节 +10,任一域命中即保留;
   - 显式选 `作者`/`分类`:仅保留该域命中的行(子串/去空格比较),并在日志提示「网络仍按书名发起,作者/分类在返回结果内过滤」。
4. P2:`作者:xxx 分类:yyy` 前缀语法、结果表域高亮、按域排序。

### 3.6 性能

- 勾选 N 个大表合并后源数可达数万;`_searchable` 预筛后搜索轮 24 workers 不变,**不设硬上限**,但合并源数 > 5000 时日志警示(可先校验再搜)。
- 校验总时长 = Σ(各文件);顺序编排天然限流,无并发叠加。

## 4. 记忆与迁移(F)

| 字段 | 语义 | 清除记忆时 |
|---|---|---|
| selected | 选中书目(不变) | 清 |
| sources | 勾选文件列表(新) | 清(回到默认单文件) |
| verify_dones | 每文件校验记录(新) | 清 |
| fuzzy/rel/fmt/mode | 选项(今日已做) | 回默认 |
| verify_origin/verify_done | 旧单文件字段 | 只读迁移后不再写 |

- 文件从勾选移除 → 该文件贡献的 selected 条目**保留**(键不含文件维度,restore_filter 自动跳过当前不存在的行,再勾回来可恢复)。
